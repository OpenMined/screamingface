# url4-cloud — technical specification (v1)

## 0. Status
Proposed. **url4-cloud supersedes the planned `apps/runner` (OME-443)** as the runner MVP: NATS
+ k8s Jobs, but leaner (one job per token, JWT topic-capability, run-once, 16 h cap). OME-443's
advanced features — recursion via child sessions, singleton reaper, external nodes, per-tree
budgets — are **deferred enhancements**, not v1. Implementation starts only on explicit owner
approval; the plan follows approval.

## 1. Purpose & scope
### 1.1 What it is
A distributed service with **two entrypoints from one image**:
- **The App** — a **stateless** k8s **Deployment + Service + Ingress** that speaks **only REST +
  WebSocket**. It mints capability tokens, **schedules k8s Jobs**, and bridges NATS → WebSocket.
- **The Runner** (`url4_cloud_runner`) — a **k8s Job** that executes a url4 expression (via
  `packages/url4`) and **publishes all telemetry to NATS** (the frames of §7).

NATS integration is a **separate internal package** (`url4_cloud_nats`) shared by both.

### 1.2 What it provides
- REST: `POST /token`, `GET /?q=<url4>` (start), `DELETE` (stop) — §5.
- WebSocket: one merged, resumable telemetry stream per token/topic, bridged from NATS — §6.
- A **JobRunner port** with a **k8s** adapter (prod) and a **Docker** adapter (local/compose e2e).
- k8s **RBAC bootstrap** so the App can manage Jobs in its own namespace — §9.
- `docker-compose.yml` for **end-to-end tests** without a cluster — §11.

### 1.3 Non-goals (v1, deferred from OME-443)
Recursion / internal child sessions; singleton reaper + fencing; external (uncontrolled) nodes;
per-tree container budgets; a persistent trace store beyond NATS JetStream retention;
multi-tenant identity (auth is a per-topic capability token, §4).

## 2. Architecture
### 2.1 Flow
```
POST /token ─────────────▶ App: mint topic = rand64[A-Za-z0-9]; JWT{sub:topic, iat}; sign HS256(JWT_SECRET)
client opens WS (JWT) ───▶ App: subscribe NATS topic <sub>; stream frames ↓ to client
GET /?q=<url4> (JWT) ────▶ App: verify (now-iat ≤ 60s, topic not already run) → schedule k8s Job
                                Job: run url4 Executor → publish Log/Span/CostUsage/... to NATS <sub>
                                App: bridge NATS <sub> ──▶ WS ──▶ client
DELETE (JWT) ───────────▶ App: stop the Job for <sub>; purge the JetStream stream for <sub>
```
Ordering guarantee: the client opens the WS (starts NATS listening) **before** start; both fall
inside the 60 s-from-`iat` window (§4), so no early telemetry is missed (JetStream replay covers
any residual gap).

### 2.2 Components (nested packages — §10)
| Package | Role |
|---|---|
| `url4_cloud` | The App: `auth/` (token+JWT), `rest/`, `ws/` (NATS→WS bridge), `jobs/` (JobRunner port + adapters). |
| `url4_cloud_runner` | The Job entrypoint: run url4, publish frames to NATS. |
| `url4_cloud_nats` | The NATS package (separate): publish, subscribe, per-topic JetStream stream, cleanup. |
| `url4_cloud_protocol` | The frame models (§7) — one contract shared by App, Runner, NATS. |

### 2.3 Reused vs deferred from OME-443
**Reused:** §6 event envelope + three signals + cost authority; §7 JobRunner **run-once**
contract (`backoffLimit:0`/`restartPolicy:Never`; retry = new token/new job); §3 absorbing
terminal state. **Deferred:** everything in §1.3.

## 3. Run state
`scheduled → running → {succeeded | failed | stopped | timed_out}`; terminal is absorbing. State
is **not** held by the App (it is stateless) — it is derived from the k8s Job status and the
NATS terminal frame. `activeDeadlineSeconds = 57600` (16 h) is the hard timeout.

## 4. Auth — JWT topic-capability (stateless)
- **`POST /token`** → generate `topic = 64 × [A-Za-z0-9]`; build `JWT { sub: topic, iat: <now> }`;
  sign **HS256** with env **`JWT_SECRET`**; return the compact JWT. `iat` is **mandatory**. No
  server-side state is stored — the token *is* the capability to its topic.
- **Validation (every authed call):** verify signature + `iat` present. Because the App is
  stateless, the only trusted clock is `iat`; the **1-minute window** is measured from it:
  - `GET` start is rejected **`401 JWT expired`** when `now − iat > 60 s`.
  - The WS connect and the start therefore both fall inside the 60 s window (§2.1).
  - **Start requires an active NATS subscriber on `sub`** (a NATS interest check — still
    stateless): if the client's WebSocket isn't attached, the start is rejected
    `428 Precondition Required` ("attach the WebSocket to the topic before starting"). Guarantees
    no run begins with nobody listening — belt-and-suspenders with the 60 s window + JetStream
    replay.
- The `topic` (`sub`) is the routing key for NATS and the identity for start/stop.

## 5. REST API
- **`POST /token`** — §4. `⇒ { token }`. No auth.
- **`GET /?q=<url4-expr>`** *(JWT `Authorization: Bearer`)* — schedule the Runner Job for `sub`.
  The url4 expression rides as the **URL-encoded `q` query param** (expressions carry `()!,;:/`).
  **Sync vs async is selected with the standard `Prefer` header (RFC 7240):**
  - **`Prefer: respond-async`** → schedule and return at once: `202 Accepted` +
    `Location: /?topic=<sub>` + `Preference-Applied: respond-async`. Success = *Job scheduled &
    running*.
  - **no `Prefer`** (or `Prefer: wait=<s>`) → **synchronous**: hold the request while the App
    subscribes NATS and awaits the terminal frame, bounded by `min(wait, SYNC_MAX_WAIT)` (config;
    default aligned to the ingress read timeout). If the run outlives the bound → `202 Accepted` +
    `Location` (**degrade to async** — the RFC 7240 `respond-async, wait` pattern). *Long runs (up
    to the 16 h cap) are always async; sync is for short ones — no ingress holds a 16 h request.*
  - Common errors: `401 JWT expired` (`now − iat > 60 s`); `409 Conflict` when a Job for `sub`
    **already ran** — tokens are single-use, checked by the Job's **deterministic name**
    (`url4-<hash(sub)>`), so the check stays stateless. Job: `activeDeadlineSeconds = 57600`
    (16 h), `backoffLimit: 0`, `restartPolicy: Never`.

  **Sync outcome → HTTP** (body carries `Result` or `ErrorInfo{code,message,permanent}`):

  | `Terminated.status` | HTTP |
  |---|---|
  | succeeded | `200 OK` + `Result` |
  | failed | `502 Bad Gateway` (App is a gateway to the Job) |
  | timed_out (16 h deadline) | `504 Gateway Timeout` |
  | stopped (via `DELETE`) | `409 Conflict` |
  | exceeded `SYNC_MAX_WAIT` | `202 Accepted` + `Location` (degrade to async) |

  *GET-with-side-effect is intentional (url4 doctrine N1: expression-as-address ⇒ GET); the
  `409-on-repeat` rule makes it single-shot, not idempotent-replay.*
- **`DELETE /?topic=<sub>`** *(JWT)* — `JobRunner.stop(sub)` (idempotent) + purge the JetStream
  stream for `sub`. `⇒ 204`.

## 6. WebSocket
`GET /ws` *(JWT)* — the App subscribes the NATS topic `sub` and streams the merged
`OutboundFrame` sequence (§7) to the client. Opened **before** start (§2.1). Reliability:
per-stream monotonic `seq` (dedup); `Attach{from_seq}` replays the gap then goes live
(reconnect = resume); `Heartbeat` for liveness; the terminal frame is durable in JetStream so a
late/reconnecting client still converges to the outcome.

## 7. Frame models (Pydantic v2) — published by the Runner, streamed by the App
```python
from datetime import datetime
from decimal import Decimal
from typing import Annotated, AsyncIterator, Literal, Protocol, Union
from pydantic import BaseModel, ConfigDict, Field, model_validator

class FrameBase(BaseModel):
    model_config = ConfigDict(extra="forbid")
    v: int = 1
    trace_id: str            # == topic (sub)
    node_id: str
    span_id: str | None = None
    parent_span_id: str | None = None
    seq: int = 0             # monotonic per stream — dedup/resume identity
    ts: datetime

class TokenUsage(BaseModel):
    model_config = ConfigDict(extra="forbid")
    input_tokens: int = 0
    output_tokens: int = 0
    cache_read_tokens: int = 0
    cache_creation_tokens: int = 0
    reasoning_tokens: int = 0

class CostBreakdown(BaseModel):
    model_config = ConfigDict(extra="forbid")
    input_usd: Decimal = Decimal("0")
    output_usd: Decimal = Decimal("0")
    cache_read_usd: Decimal = Decimal("0")
    cache_creation_usd: Decimal = Decimal("0")
    reasoning_usd: Decimal = Decimal("0")
    total_usd: Decimal
    @model_validator(mode="after")
    def _total_is_sum(self):
        parts = (self.input_usd + self.output_usd + self.cache_read_usd
                 + self.cache_creation_usd + self.reasoning_usd)
        if self.total_usd != parts:
            raise ValueError(f"total_usd {self.total_usd} != Σ parts {parts}")
        return self

class ErrorInfo(BaseModel):
    code: str; message: str; permanent: bool = False   # mirrors url4 Url4Error

class Started(FrameBase):
    type: Literal["started"] = "started"; url4: str
class Log(FrameBase):
    type: Literal["log"] = "log"
    level: Literal["debug", "info", "warning", "error"]; message: str
    fields: dict[str, str | int | float | bool | None] = {}
class Span(FrameBase):                       # OTel gen_ai.* — TOKENS here, cost NOT
    type: Literal["span"] = "span"
    name: str; operation: str; provider: str | None = None
    request_model: str | None = None; response_model: str | None = None
    input_tokens: int | None = None; output_tokens: int | None = None
    start_ts: datetime; end_ts: datetime | None = None
    status: Literal["ok", "error"] = "ok"
class CostUsage(FrameBase):                   # separate taxonomy event
    type: Literal["cost.usage"] = "cost.usage"
    scope: Literal["self", "subtree"]
    provider: str; model: str; pricing_version: str
    usage: TokenUsage; cost: CostBreakdown
class Heartbeat(FrameBase):
    type: Literal["heartbeat"] = "heartbeat"
class Result(FrameBase):
    type: Literal["result"] = "result"; body: str; media_type: str | None = None
class Terminated(FrameBase):
    type: Literal["terminated"] = "terminated"
    status: Literal["succeeded", "failed", "stopped", "timed_out"]
    error: ErrorInfo | None = None

OutboundFrame = Annotated[
    Union[Started, Log, Span, CostUsage, Heartbeat, Result, Terminated],
    Field(discriminator="type")]
```
Design rules: discriminated union on `type` (clean `oneOf` for §12); money `Decimal` →
JSON string on the wire; tokens on `Span`, cost a separate `CostUsage`; `ErrorInfo` mirrors
`Url4Error` so serialized failures drive `GuardNode` identically; `seq` monotonic per stream.

### 7.1 Authoring for Scalar-grade OpenAPI docs
Every model is written so FastAPI's generated OpenAPI 3.1 renders as a **beautiful, accurate,
fully-documented** reference in **Scalar** — achieved by authoring, never post-editing. The
conventions (applied to every model/field, shown here on `CostUsage`):
- `model_config = ConfigDict(use_attribute_docstrings=True, title=…, json_schema_extra={"examples":[…]})`
  — attribute docstrings become field `description`s (Pydantic ≥ 2.7); a class-level example fills
  Scalar's sample panes.
- `datetime` → `format: date-time`; money is a **string** on the wire (`Decimal`) with an example;
  the discriminated union carries a `discriminator` mapping so Scalar shows a clean variant picker.

```python
class CostUsage(FrameBase):
    """A single node's cost + token usage — a taxonomy event, never a span attribute."""
    model_config = ConfigDict(
        use_attribute_docstrings=True,
        title="Cost / usage event",
        json_schema_extra={"examples": [{
            "type": "cost.usage", "trace_id": "9f2c…", "node_id": "root", "seq": 7,
            "ts": "2026-07-21T09:00:03Z", "scope": "self", "provider": "anthropic",
            "model": "claude-opus-4-8", "pricing_version": "2026-07-01",
            "usage": {"input_tokens": 1200, "output_tokens": 340},
            "cost": {"input_usd": "0.0180", "output_usd": "0.0255", "total_usd": "0.0435"}}]})
    type: Literal["cost.usage"] = "cost.usage"
    scope: Literal["self", "subtree"]
    """`self` = this node only (authoritative); `subtree` = self + Σ descendants."""
    provider: str
    """Model provider, e.g. `anthropic`, `openai`."""
    model: str
    pricing_version: str
    """Pricing table version the USD figures were derived from."""
    usage: TokenUsage
    cost: CostBreakdown
```

## 8. Taxonomy invariants (what the Runner/mock must satisfy)
`total_usd == Σ parts` (model-enforced); per node `CostUsage{self}` authoritative and
`subtree == self + Σ children.subtree`; root `subtree.total == Σ all self`; cost derived from
`usage × pricing_version`; `CostUsage{subtree}` emitted before `Result`; monotonic `seq`;
well-formed span tree (every `parent_span_id` refers to an emitted parent).

## 9. k8s deployment & RBAC bootstrap
- **App:** `Deployment` + `Service` + `Ingress` (REST + WS); `ConfigMap` (NATS URL, window) +
  `Secret` (`JWT_SECRET`). ConfigMap also carries `NATS_URL`, the `iat` window (60 s), and
  `SYNC_MAX_WAIT` (the sync-hold cap, §5).
- **RBAC (namespace-scoped):** a `ServiceAccount` for the App + a `Role` granting
  `batch/jobs: create, get, list, watch, delete` (and `pods: get, list, log` for status/logs) +
  a `RoleBinding`. This is the "first-deployment bootstrap" that lets the App run Jobs **only in
  its own namespace**.
- **Runner Job template:** image = same app image, entrypoint `url4_cloud_runner`; env carries
  `topic`, `NATS_URL`, the url4 expression; `activeDeadlineSeconds: 57600`, `backoffLimit: 0`,
  `restartPolicy: Never`.
- **NATS:** deployed as a chart dependency (JetStream enabled). Helm chart clones the scoreboard
  `charts/<app>` pattern (per OME-443 §P5).

### 10.1 Pre-commit & quality-gate wiring
url4-cloud is the **first** stack to add the **pre-commit** framework. Because the repo runs hooks
from a committed `.githooks/` dir (`core.hooksPath`), not `.git/hooks/`, pre-commit is chained
through it — the framework's default install is ignored otherwise.
- **`.pre-commit-config.yaml`** (repo root) — fast hooks gating **every commit**: `ruff-check`
  (incl. `C901`/PLR) · `ruff-format` · `pyright` · pre-commit-hooks std (trailing-whitespace,
  end-of-file-fixer, check-yaml, check-toml, check-added-large-files, check-merge-conflict).
- **Heavy suite** — `uv run .claude/scripts/run_gates.py url4-cloud` (pytest + coverage) on
  **pre-push** and in CI, not per commit, so commits stay fast.
- **`.githooks/pre-commit`** — keep the no-commit-to-main guard, then `pre-commit run` on staged
  files; **`.githooks/pre-push`** runs `run_gates.py` for changed stacks.
- **Setup:** `git config core.hooksPath .githooks` (currently mis-set to a stale
  `apps/desktop/.husky/_` from the removed legacy app — must be fixed) + `uv run pre-commit install`.
- **Landing = `repo`** — this is repo infrastructure (root config + `.githooks`), best filed as its
  own `repo`-landing ticket that lands before the url4-cloud package code.

## 11. docker-compose e2e
`docker-compose.yml` brings up **NATS (JetStream) + the App + a Docker "job" adapter** that runs
a **mock runner** (publishes logically-correct fake frames, §8) — because compose can't run real
k8s Jobs. e2e smoke: `POST /token` → open WS → `GET /?q=…` → assert the streamed frames validate
against the §12 schemas and satisfy §8 → `DELETE` → assert stream purged. The `JobRunner` port's
Docker adapter is what makes prod (k8s) and e2e (compose) the same code path.

## 12. OpenAPI 3.1 + AsyncAPI 3.0 + Scalar docs (primary deliverable)
`url4_cloud_protocol` emits one JSON-Schema (2020-12) set. **OpenAPI 3.1** describes the REST
paths (§5) + `$ref`s the schemas; **AsyncAPI 3.0** describes the `/ws` channel + messages +
`$ref`s the same schemas. Generated in CI, checked in.

**Scalar-grade quality (a hard requirement).** The app serves a **Scalar** API reference at
`/scalar` (rendering `/openapi.json`) that must read as a polished, accurate, fully-documented
reference — achieved by authoring:
- **Models** per §7.1 (titles, attribute-docstring descriptions, per-model + per-field examples,
  discriminator mapping so variants render as a picker).
- **`info`** block: title, rich markdown `description`, `version`, `contact`, `license`.
- **Operations**: each route carries `summary`, markdown `description`, `tags` (`Token` ·
  `Execution` · `Stream`), a stable `operation_id`, documented `Prefer`/`Preference-Applied`
  headers, and **`responses` for every status** (200/202/401/409/502/504) each with a `model` +
  a realistic `example` — so Scalar shows every outcome, not just the happy path.
- **CI doc gate**: fail if any exposed model/field lacks a `description`/example, or the OpenAPI
  doesn't lint clean (Spectral) — so the reference can't silently rot (same philosophy as the
  complexity gate).

## 14. Decisions locked
1. url4-cloud **supersedes** `apps/runner` (OME-443); OME-443 advanced features deferred.
2. Two entrypoints, one image: `url4_cloud` (App) + `url4_cloud_runner` (Job); `url4_cloud_nats`
   is a separate package; `url4_cloud_protocol` holds the shared frames.
3. Auth = stateless JWT `{sub: topic, iat}`, HS256/`JWT_SECRET`; start rejected if `now−iat>60 s`.
4. `POST /token` · `GET /?q=<url4>` (start, single-use → 409 on repeat) · `DELETE` (stop+purge);
   Job run-once, `activeDeadlineSeconds=57600` (16 h).
5. WS bridges NATS `sub` → client; open-before-start; resume via `seq`.
6. JobRunner port with k8s (prod) + Docker (compose e2e) adapters; RBAC bootstrap in-namespace.
7. Deliverable = OpenAPI 3.1 (REST) + AsyncAPI 3.0 (WS) over one JSON-Schema set.
8. App lands at `apps/url4-cloud`; landing label `url4-cloud`.
9. Sync/async selected via `Prefer: respond-async` (RFC 7240): async → `202` + `Location`; sync
   is bounded by `min(Prefer: wait, SYNC_MAX_WAIT)` and **degrades to `202`** past the bound;
   sync outcome maps `Terminated.status` → HTTP (200 / 502 / 504 / 409).
10. Docs are **Scalar-grade by construction**: models authored per §7.1, every operation fully
    documented with per-status examples, served via **Scalar** at `/scalar`, enforced by a CI
    description/example-coverage + OpenAPI-lint (Spectral) gate.
