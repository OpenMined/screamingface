Minimal CLI + HTTP server exposing the `url4` engine as a runnable url4 node, shipped as an
optional `url4[serve]` extra on `packages/url4`. `url4 serve` stands up a Starlette/uvicorn
endpoint (`GET /?q=` transactional, `POST /` escape hatch, `/healthz`) that evaluates url4
expressions; a dispatching `IOLayer` routes leaves to the aigegateway (`/v1/chat/completions`,
`provider/model`) for LLM routes, to local subprocesses for opt-in command routes (doctrine
N4), and to plain fetches for data reads — a registry of adapters, core never importing them
(N5). `--processor` selects the reduce route (validated at startup). Companion `url4 eval`
runs network-free (StaticIOLayer). Backpressure via `--max-inflight` (503), per-request
timeout, graceful shutdown. Streaming/telemetry/daemonization deferred.

Note: filed with `pkg/url4-python-sdk` + `autonomous` + `agentic` only — the card's Epic
workstream group (e.g. "url4 Engine") has been removed from Linear; card taxonomy needs an
owner reconcile.

**Scope extension (2026-07-16, owner-directed, same PR):** the aigateway connector is
removed — `url4 serve` keeps ONE route concept, `[commands]` (user-owned subprocess argv
templates; an LLM backend is the user's own gateway script mounted as a command). The
serve-layer `processor` config is renamed `default_route`: must name a declared command
route, defaults to the first declared one; empty `[commands]` fails fast. Core SDK keeps
the `processor` name but drops the hardcoded `/claude` default (Url4Node: first registered
endpoint; bare engine: clear error on reduce without one). See the ledger's Scope
extension section.
