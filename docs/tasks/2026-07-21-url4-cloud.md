# OME-513 — url4-cloud app (epic)

Single-process app (`apps/url4-cloud`, Python · uv · FastAPI) running the url4 engine and an
external tool in one process over an in-process duplex `asyncio` **Channel**, exposing a
**REST + WebSocket** protocol that streams logs, telemetry (OTel `gen_ai.*` spans) and taxonomy
(tokens + USD cost, `self`/`subtree`) from all nodes over one merged stream.

**Reuses** OME-443's event/taxonomy data model (§3 state, §6 envelope + three signals + cost
authority); **drops** its distributed topology (no NATS/JobRunner/reaper). Distinct app from
the planned `apps/runner`.

**Locked decisions:** one duplex `Channel` port (same frames in-proc and over WS; JSON only at
the WS edge) · Pydantic v2 frame models (discriminated union on `type`; `Decimal` money; tokens
on spans, cost a separate `cost.usage` event) · engine seam (OME-446) assumed → `MockEngineChannel`
emits logically-correct fakes · primary deliverable OpenAPI 3.1 + AsyncAPI 3.0 on one schema set.
