# OME-466 — url4 serve: minimal CLI to run the engine as an HTTP node

## Intent

Expose the framework-free `url4` engine as a runnable **url4 node** via a minimal CLI +
HTTP server, shipped as an optional `url4[serve]` extra on `packages/url4`. A user runs
`url4 serve` to stand up an endpoint that evaluates url4 expressions — fanning out model
calls to the aigateway (`:9105`) and dispatching custom/command routes locally — realizing
the doctrine's "url4 expression IS the address" node model (N1/N4/N5) at the SDK layer.
Companion `url4 eval` gives a network-free one-shot. Keeps the core import graph
framework-free (Starlette/uvicorn quarantined behind the extra, like `io_http` quarantines
httpx).

## Planned changes (REVISED — built on existing `Url4Node`; see spec/plan pivot)

- `packages/url4/pyproject.toml` — `[project.scripts] url4 = "url4.cli:main"`. Reuses the
  existing `[project.optional-dependencies] server = ["uvicorn"]` extra. **No Starlette.**
- `packages/url4/src/url4/_serve.py` — `ServeConfig` + `resolve()`/`validate()` (flag > env >
  url4.toml > default); `DEFAULT_ROUTES`; `make_llm_handler` (aigateway `/v1/chat/completions`),
  `make_command_handler` (subprocess); `build_node(config, client)` wiring `@node.endpoint`
  handlers + `data("/healthz","ok")` onto a `Url4Node`; `build_asgi_app(...)` raw-ASGI wrapper
  adding 503 backpressure / 504 timeout / graceful client+node shutdown.
- `packages/url4/src/url4/cli.py` — argparse CLI: `serve` / `eval` / `--version`; stdout/stderr
  discipline; exit codes 0/1/2; lazy uvicorn seam (`_serve_forever`).

  — keep `--cov=url4` ≥ 95%.
- `docs/spec/…`, `docs/plan/…`, `docs/tasks/…` (created; pivot noted).

**Superseded plan:** the original `url4/server/` subpackage + `GatewayIOLayer` + Starlette app
(`url4/server.py` already exists as the `Url4Node` SDK; a Starlette layer would duplicate it).

## Test plan

- Config resolution precedence (flag > env > toml > default); unknown `--processor` route → fail-fast; bad `--concurrency` rejected.
- IOLayer dispatch: absolute URL → plain GET; bare `/path` → plain GET; `/claude?q=(ctx)!intent` → aigateway POST body/model/auth asserted (fake transport); command route → subprocess stdout; unknown route → ResolutionError.
- prompt merge `merge(intent, ctx)` matches the engine's `default_process` convention.
- App: GET/POST eval happy path; `Url4Error` → 400/422/502/504 mapping; over `max_inflight` → 503 + Retry-After; `/healthz` no-run; graceful shutdown closes the client.
- CLI: `eval` from arg + stdin (StaticIOLayer); `--version`; usage error → exit 2; serve wiring smoke (bind + immediate shutdown).

## Post-review follow-up (2026-07-15) — commit `0a211fe`

Ran `/qa-tester` + `/simplify` + `/code-review` over the branch. Code was structurally
clean (no simplifications applied — apparent duplication vs `server.py` is justified by
divergent behavior); review surfaced two latent edge-case bugs, both fixed with regression
tests on the same branch/PR:

- **eval-path/`/healthz` clash** — `ServeConfig.validate()` guarded routes/commands against
  the reserved paths but not `eval_path == /healthz`; `url4 serve --eval-path /healthz`
  collided at `build_node` time with an uncaught `ValueError` (traceback, exit 1) instead of
  a fail-fast `ConfigError` (exit 2). Added a `validate()` guard.
- **non-UTF-8 command output** — `_run_command` decoded subprocess stdout/stderr strictly;
  a command exiting 0 with non-UTF-8 output raised a raw `UnicodeDecodeError`, bypassing the
  `Url4Error → HTTP` mapping (bare 500). Now decodes with `errors="replace"`.

Gates re-run: ruff/format/pyright clean; `_serve.py`/`cli.py` still **100%** coverage;
full package suite **755 passed** (753 + 2 regression tests). Pushed to the PR branch.
