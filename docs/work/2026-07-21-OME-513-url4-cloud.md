# OME-513 — url4-cloud app (epic): spec, plan & ticket cascade

## Intent

Design → spec → plan `apps/url4-cloud` (Python · uv · FastAPI), a **distributed** runner that
**supersedes the planned `apps/runner` (OME-443)** as the runner MVP. One image, two entrypoints:
a **stateless App** (k8s Deployment + Service + Ingress; REST + WebSocket only) that mints JWT
topic-capability tokens, schedules **k8s Jobs**, and bridges **NATS → WebSocket**; and a
**Runner** (`url4_cloud_runner`, a k8s Job) that executes a url4 expression via `packages/url4`
and publishes telemetry (logs, OTel `gen_ai.*` spans, tokens + USD cost `self`/`subtree`) to NATS.
NATS is a separate internal package (`url4_cloud_nats`); frames live in `url4_cloud_protocol`.
Auth = stateless JWT `{sub: topic, iat}` (HS256/`JWT_SECRET`, 60 s window). Reuses OME-443's
event/taxonomy model + JobRunner run-once + RBAC/Job doctrine; defers OME-443's recursion,
reaper, external nodes, per-tree budgets. This epic unit files the sub-issue cascade, registers
the `url4-cloud` landing label, and provides a `docker-compose` e2e path.
