# OME-516 — url4_cloud_nats bus (CloudEvents NATS binding)

## Intent
The transport port shared by App (subscribe) and Runner (publish): an async `Bus` that carries
`url4_cloud_protocol` CloudEvents over a per-topic stream (docs/protocol.md §2, §8). One
JetStream stream per capability topic; the stream assigns the monotonic CloudEvents `sequence`
(§6); resume/replay from a sequence; purge on `DELETE`. Two implementations behind one port:
`NatsBus` (nats-py JetStream, real infra) and `InMemoryBus` (headless fake for tests + local).

## Planned changes
- `src/url4_cloud_nats/codec.py` — pure wire codec + subject/stream naming (`encode`/`decode`/
  `subject_for`/`stream_for`); serialize via `model_dump(mode="json", by_alias=True)`, parse via
  `OutboundFrameAdapter.validate_python`; stream-assigned `sequence` injected on read.
- `src/url4_cloud_nats/bus.py` — the `Bus` Protocol (port).
- `src/url4_cloud_nats/memory.py` — `InMemoryBus` (append-log + monotonic seq + live fan-out).
- `src/url4_cloud_nats/nats_bus.py` — `NatsBus` (JetStream add_stream/publish/subscribe/purge).
- `src/url4_cloud_nats/__init__.py` — export `Bus`, `InMemoryBus`, `NatsBus`.
- `tests/unit/test_nats_bus.py` — InMemoryBus behavior + port conformance.

## Test plan (InMemoryBus only — no live NATS, per INFRA rule)
- publish→subscribe round-trips CloudEvents **in order** (real encode/decode);
- gen_ai.* alias round-trip survives the codec (SpanEvent tokens);
- `sequence` monotonic, `sequencetype == "Integer"`;
- `subscribe(from_sequence=N)` replays the gap inclusively;
- live delivery (subscribe opened before publish);
- `purge` clears buffered frames while the stream sequence keeps counting;
- `InMemoryBus`/`NatsBus` both satisfy the `Bus` port (static + construct).

## Acceptance
- Gates green; `Bus`/`InMemoryBus`/`NatsBus` importable; NatsBus is a thin, typed JetStream shim
  (pure codec/naming logic covered via the InMemoryBus tests).

## Outcome
- **Actual files:** `src/url4_cloud_nats/{codec,bus,memory,nats_bus,__init__}.py` +
  `tests/unit/test_nats_bus.py` (7 tests) — as planned.
- **Design:** hexagonal — `Bus` Protocol is the port; `InMemoryBus` (test/local) and `NatsBus`
  (JetStream) are adapters. The wire codec + subject/stream naming live in `codec.py` and are
  shared by both adapters (DRY). `sequence` is stream-assigned (starts at 1) and injected on read
  via `decode(payload, sequence=...)`, so both adapters model JetStream's server-assigned sequence
  identically. `from_sequence` is inclusive (matches JetStream `BY_START_SEQUENCE`). `InMemoryBus`
  uses one `asyncio.Condition` per topic for correct live fan-out with no missed wakeups; it never
  holds the lock across a `yield`.
- **Gates:** `run_gates.py url4-cloud` ALL GREEN — ruff · ruff-format · pyright (clean, no
  `type: ignore`) · pytest+cov **90%** (fail-under 80). 7 new tests, all InMemoryBus + port
  conformance; no prior test touched (append-only).
- **INFRA:** no live NATS/k8s in tests. `NatsBus` network I/O (connect/add_stream/publish/subscribe/
  purge) is the only uncovered code (45% file) — deliberately deferred to the compose e2e (OME-524);
  its pure codec/naming logic is covered via the InMemoryBus round-trip. No `# pragma: no cover` and
  no gate weakening were needed (aggregate 90%).
- **Deviations:** none. `NatsBus.close()` added (not in the port) for clean connection teardown by
  callers that own the lifecycle.
