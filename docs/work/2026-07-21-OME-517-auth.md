# OME-517 — auth: topic token + JWT capability + RFC 9457 Bearer guard

## Intent
The App mints a per-run **capability topic** and a JWT that carries it, then the streaming/REST
surfaces admit a request only when its Bearer token verifies against a stateless `iat` window
(spec §4; docs/protocol.md §7 — RFC 7519 JWT + RFC 9457 Problem Details). This unit builds the
auth primitives (`url4_cloud/auth/`) that later units (OME-518 REST, OME-521 WS) depend on:
random topic id, JWT sign/verify with typed failures, a FastAPI Bearer dependency, and the
`application/problem+json` 401 rendering. **SECURITY-SENSITIVE**: HS256 signing over
`Settings.jwt_secret`; the secret and the token are never logged and never echoed in error bodies.

## Planned changes
- `src/url4_cloud/auth/__init__.py` — package exports.
- `src/url4_cloud/auth/token.py` — `new_topic()` → 64-char `[A-Za-z0-9]` via `secrets`.
- `src/url4_cloud/auth/errors.py` — typed `AuthError` hierarchy (invalid / missing-iat /
  window-exceeded / expired / missing-credentials).
- `src/url4_cloud/auth/jwt.py` — `JwtCodec.sign(topic, now)` / `.verify(token, now)` (HS256,
  registered claims `sub`/`iat`/`exp`/`jti`; stateless `now - iat > iat_window_s` guard;
  exp checked against the **injected** clock, not wall-clock).
- `src/url4_cloud/auth/problem.py` — RFC 9457 `Problem` model + `ProblemException` +
  `application/problem+json` handler + `install_problem_handlers(app)`.
- `src/url4_cloud/auth/dependencies.py` — `verified_claims` FastAPI dependency (extract Bearer,
  verify, map any `AuthError`/missing-credentials → 401 problem+json); injectable `now()` clock.
- `tests/unit/test_auth.py` — RED-first behaviour tests.

## Test plan
- `new_topic()` matches `^[A-Za-z0-9]{64}$` and is non-repeating.
- sign→verify roundtrip returns `sub==topic`, `exp==iat+iat_window_s`, `jti` present.
- tampered / wrong-secret / malformed token → `InvalidToken`.
- missing `iat` claim → `MissingIat`.
- `now - iat > iat_window_s` → `IatWindowExceeded`.
- exp respected: at the exp boundary (`now == exp`) → `TokenExpired`.
- fresh token inside window → accepted.
- dependency: valid Bearer → 200; expired/tampered/missing → 401 `application/problem+json`
  with `WWW-Authenticate: Bearer` and RFC 9457 members.
- security: error strings never contain the secret or the token.

## Acceptance
- Gates green (`run_gates.py url4-cloud`); the JWT window guard rejects stale/expired/tampered
  tokens; 401s render as RFC 9457 problem+json; no secret/token in any error surface.
