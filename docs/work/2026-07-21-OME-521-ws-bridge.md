# OME-521 — WebSocket NATS→WS bridge (CloudEvents WS binding, resume, heartbeat)

## Intent
Deliver spec §6 / protocol.md §8: a `GET /ws` CloudEvents WebSocket endpoint (subprotocol
`cloudevents.json`) that, on a JWT capability ticket, bridges the per-topic `Bus` stream to the
browser. It streams `OutboundFrame` CloudEvents as structured JSON (`by_alias` → the `gen_ai.*`
keys); accepts inbound `AttachEvent` (subscribe / resume from `from_sequence`) and `StopEvent`
(stop the Job); and emits `HeartbeatEvent`s during idle for liveness. This is the client stream
that makes `POST /token` → WS → `GET /?q=` (spec §2.1) observable, and it supplies the real
`SubscriberGate` (a live-connection registry) that the REST `428` guard was awaiting (interest.py).

## Planned changes
- `src/url4_cloud/ws/__init__.py` — export `ConnectionRegistry`, `router`.
- `src/url4_cloud/ws/registry.py` — `ConnectionRegistry` (live WS count per topic; `SubscriberGate`).
- `src/url4_cloud/ws/bridge.py` — the `Bus`→WS streaming engine (writer/inbound/subscription tasks;
  resume-on-Attach; heartbeat-on-idle; `Stop`→`JobRunner.stop`).
- `src/url4_cloud/ws/endpoint.py` — `@router.websocket("/ws")`: ticket verify, subprotocol accept,
  registry add/remove, run the bridge.
- `src/url4_cloud/config.py` — add `ws_heartbeat_s` (idle beat interval).
- `src/url4_cloud/app.py` — additively include the ws router + create the `ConnectionRegistry`,
  use it as the default `interest` gate (realizing the interest.py OME-521 note).
- `tests/unit/test_ws.py` — new.

## Test plan (RED first)
- Streams published events in order as CloudEvents JSON (`by_alias`: `sequence` string, cost
  `gen_ai.provider.name`) after an `Attach`.
- `Attach{from_sequence=2}` replays from seq 2 (resume), skipping seq 1.
- Idle connection receives a `HeartbeatEvent`.
- Inbound `StopEvent` calls `JobRunner.stop(topic)`.
- Invalid / missing ticket → connection rejected (WebSocketDisconnect); `bus is None` → rejected.
- End-to-end: a live WS flips the REST `428` gate → `GET` respond-async `202`.
- `ConnectionRegistry` add/remove counting; `DenyAllGate` reports no subscriber.

## Acceptance
- Gates green (`run_gates.py url4-cloud`); the WS streams/replays/heartbeats headless via
  `TestClient.websocket_connect` + `InMemoryBus`; REST behavior unchanged (428 still 428 with no WS).

- **Deviations:**
  - The default `interest` gate changed from `DenyAllGate` to the live-connection
    `ConnectionRegistry` — this realizes the interest.py OME-521 note ("the real gate wires in with

    shutdown path), not only a graceful `WebSocketDisconnect`.
