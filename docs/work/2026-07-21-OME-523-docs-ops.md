# OME-523 — OpenAPI 3.1 + AsyncAPI 3.0 + Scalar + ops endpoints

## Intent
Make the url4-cloud control plane self-describing and operable (spec §12; protocol.md §9). Serve a
Scalar-grade API reference at `/scalar` over the FastAPI-generated OpenAPI 3.1 (enriched with the
`url4_streaming_protocol` CloudEvents component schemas + a rich `info` block); publish an AsyncAPI
3.0 document for the `/ws` channel that `$ref`s the same CloudEvents message schemas; and add the
k8s liveness/readiness probes (`/livez`, `/readyz`) plus an OpenMetrics `/metrics` endpoint
(prometheus-client: an HTTP request counter + a placeholder `gen_ai` token counter).

## Planned changes
- `src/url4_cloud/metrics.py` — per-app `CollectorRegistry` + request/gen_ai counters + pure-ASGI
  `MetricsMiddleware`.
- `src/url4_cloud/schemas/{__init__,protocol_schemas,openapi,asyncapi}.py` — shared CloudEvents
  component schemas; `customize_openapi(app)`; `build_asyncapi()`.
- `src/url4_cloud/ops.py` — router: `/livez`, `/readyz`, `/metrics`, `/scalar`, `/asyncapi.json`.
- `src/url4_cloud/app.py` — additive wiring (metrics state + middleware, ops router, openapi).
- `apps/url4-cloud/pyproject.toml` — add `prometheus-client`.
- `tests/unit/test_docs_ops.py` — the DOC-GATE + ops behaviour tests (RED first).

## Test plan
- DOC-GATE: `app.openapi()` — every `components.schemas` entry has a non-empty `description` or
  `title`; `CostUsageData` is present and carries an `example`; the CloudEvents events (incl.
  `CostUsageEvent`) are exposed as component schemas.
- `/scalar` → 200, `text/html`, references `/openapi.json`.
- `/livez` + `/readyz` → 200.
- `/metrics` → 200, `text/plain`, OpenMetrics body carrying the request + gen_ai token counters.
- `/asyncapi.json` → 200 AsyncAPI `3.0.0` with a `/ws` channel + inbound/outbound message refs.

## Acceptance
- Gates green; docs render from `/scalar`; probes + metrics live; AsyncAPI validates structurally.
