# OME-643 — Add 09_reproduce_a_result.ipynb — a 10-minute presentation demo

## Intent

Repackage the strongest parts of `08_draco_explained.ipynb` as a stepped, slide-like
presentation notebook for a ~10-minute live demo to the authors of an ensemble paper — showing
ScreamingFace as the infrastructure partner that reproduces their result. Quick Start first
(connect → load → compose → evaluate → read the gain), then build up to the full 16-candidate
DRACO study. Cards carry the visuals; the raw URL4/rubric verbosity of `08` is removed.

## Planned changes

- Create `packages/screamingface/examples/09_reproduce_a_result.ipynb` (~18 cells).
- Presentation asset: `docs/diagrams/screamingface-request-architecture-{light,dark}.{svg,png}`
  — researcher client → SF engine → AI Gateway → providers, with HF datasets + Tavily hanging off
  the engine. On-brand (screamingface-design): square corners, hairlines, mono, greyscale + one
  amber spark on the engine; light and dark. Generated by a script, rendered with `rsvg-convert -z 2`.

Cell arc: intro slide (engine: what/how/providers/BYOK/subsidized compute) → Quick Start
(`sf.connect()` panel, `sf.models.view()`, `sf.benchmarks.load("draco-lite@1")` card, one
`sf.Fusion` card, live `draco.evaluate(fusion)` report card, read the gain) → Scale up (full
7-solo + 9-Fusion topology reused verbatim from `08` cell 7, `draco.evaluate(candidates)` study
card, pre-run before demo) → "what the engine did" recap → why-partner close.

## Test plan

Example notebook (docs-like) — no unit tests. Verification is a clean end-to-end run:

- Notebook executes top-to-bottom against a live engine; every card renders (connection panel,
  models catalog, benchmark, fusion, report, study report).
- No raw URL4 / rubric text prints anywhere outside a card.
- Quick Start live run shows a `gain`; full-study card renders all 16 candidates with a `best`.

## Acceptance

- The three above, plus a read-through narration landing near ~10 minutes.
