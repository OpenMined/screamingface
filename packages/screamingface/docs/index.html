ScreamingFace API and URL4 execution guide

Compose model calls as one shareable URL4 recipe, execute the graph through a URL4 node, then compare the fused answer with the same individual answers.

Current development state The orchestration path is real; the default model answers are deterministic. The zero-setup engine is a real in-process Url4Node. It parses bindings, schedules dependencies, dispatches routes, and builds the result. Its model routes currently use deterministic model-route handlers instead of AI Gateway or providers, so teammates can run every example without credentials. Those scores demonstrate mechanics, not model quality.

Smallest complete run

import screamingface as sf

fusion = sf.Fusion(
    "frontier-trio",
    models=[
        "codex/gpt-5.5",
        "gemini-cli/gemini-2.5-pro",
        "anthropic/claude-sonnet-4-6",
    ],
    reducer=sf.MajorityVote(tie_breaker="codex/gpt-5.5"),
)

run = fusion.evaluate("gpqa", first=20, seed=0)
run.score, run.baseline, run.gain
# (100.0, 80.0, 20.0) — deterministic demonstration, not provider evidence

Execution architecture

ScreamingFace owns experiment composition, benchmark adaptation, deterministic reducers, grading, and comparison. URL4 owns expression parsing, binding resolution, dependency execution, and route dispatch. ScreamingFace never calls AI Gateway directly; only a production URL4 model-route adapter may do that.

Production leaf only: URL4 route → AI Gateway → provider

No configuration

engine="mock", synthetic benchmark fixture. Complete URL4 execution happens in-process.

Live data only

sf.config(mode="live") fetches the live dataset but keeps deterministic model routes. Data provenance does not imply provider inference.

HTTP engine

sf.config("http://127.0.0.1:4404") uses strict HTTP and the synthetic fixture. Engine failures remain visible.

No silent fallback Selecting an HTTP engine never falls back to deterministic responses when the server is unavailable. EngineUnavailable is raised instead.

Recipe, request, and response

fusion.url4 is an unresolved, shareable recipe. It is URL4 source text rather than an https:// location. Evaluation binds one concrete benchmark prompt, then gives the complete expression to the selected engine.

1 · Shareable recipe

(
  panel_1=/codex/gpt-5.5()!'$question',
  panel_2=/gemini/2.5()!'$question',
  panel_3=/claude/sonnet-4.6()!'$question',
  {
    schema: 'screamingface.panel-result.v2',
    panel_1_id: 'codex/gpt-5.5',
    panel_1_model: 'codex/gpt-5.5',
    panel_1_answer: '$panel_1',
    ...
  }
)

2 · Concrete expression

(
  question='Which option is correct? ... Reply with only A, B, C, or D.',
  panel_1=/codex/gpt-5.5()!'$question',
  panel_2=/gemini/2.5()!'$question',
  panel_3=/claude/sonnet-4.6()!'$question',
  {schema: 'screamingface.panel-result.v2', ...}
)

3 · HTTP transport when selected

GET /v1?q=<percent-encoded concrete expression>
Host: 127.0.0.1:4404
Accept: */*

The default in-process engine evaluates the same decoded expression without creating this HTTP request.

{
  "schema": "screamingface.fusion-result.v2",
  "panel_1_id": "codex/gpt-5.5",
  "panel_1_model": "codex/gpt-5.5",
  "panel_1_answer": "A",
  "panel_2_id": "gemini-cli/gemini-2.5-pro",
  "panel_2_model": "gemini-cli/gemini-2.5-pro",
  "panel_2_answer": "B",
  "reducer": "model",
  "reducer_model": "codex/gpt-5.5",
  "answer": "A"
}

Stable slot IDs keep repeated calls to the same underlying model distinct. ScreamingFace validates model/slot association before reducing or grading the response.

What is mocked today?

The selected default engine is screamingface._mock_engine.MockUrl4Engine. It passes the complete expression to a real Url4Node.evaluate(). URL4 invokes deterministic handlers registered for /codex/gpt-5.5, /gemini/2.5, /claude/sonnet-4.6, and the DRACO judge route. The handlers return stable text where production handlers would call AI Gateway. Parsing, graph execution, bindings, response construction, SDK reduction, and grading are not replaced by canned Run objects.

Configuration and lifecycle

config

config(engine=None, *, mode="mock", static_widgets=False, engine_client=None) -> Session

Replace the active process-local session. engine is "mock" or an HTTP(S) base URL. mode independently chooses bundled fixture data or live dataset loading. engine_client is an advanced injected engine port for tests and adapters.

Session

Session(mode="mock", engine_url="mock", static_widgets=False, dataset_source="synthetic-gpqa-shaped", engine=None)

Holds process-local engine and dataset selection. Most users let Fusion.evaluate() create the default session or call config(). close() marks a session unusable.

current_session

current_session() -> Session | None

Return the active session without creating one.

reset_session

reset_session() -> None

Close and remove the active session. The next evaluation recreates the zero-setup default.

shutdown

shutdown() -> None

Close session state and the SDK's synchronous async worker. Useful in tests and long-lived processes.

Models and fusion composition

models

models.list(*, max_price=None) -> list[str] · models.get(model_id) -> Model

Access the SDK route catalog. The current listed catalog is intentionally small and deterministic. max_price is optional metadata filtering; examples do not depend on it.

ModelConfig

{"model": str, "name"?: str, "prompt"?: str, "params"?: dict[str, str | int | float | bool]}

A strict typed dictionary for one configured panel call. A model ID string is shorthand for {"model": model_id}. Use name to distinguish repeated calls to the same model.

Fusion

Fusion(name, models, reducer=None, *, prompt="$question", tools=())

Validate and compile at least two model calls into canonical URL4. Important members: url4, models, model_ids, request_for(prompt), from_yaml(path), and evaluate(benchmark, first=20, seed=0, progress=None). Construction performs no model or network work.

Reduction

Reducer

abstract base contract

The public type category for turning completed panel outputs into one answer. Use a concrete built-in mechanism rather than constructing this class.

MajorityVote

MajorityVote(tie_breaker: str | None = None)

A local deterministic reducer. tie_breaker identifies an existing configured call and never creates another model request.

ModelReducer

ModelReducer(*, model, prompt, params=None)

Add model-backed reduction to the URL4 graph. The prompt may synthesize, rank, select, merge, or adjudicate; use $question and $panel_answers bindings. Its params have the same URL4 semantics as panel-call parameters.

Results

Run

immutable benchmark result

Key values are score, baseline, gain, engine, mode, dataset_source, model_results, failures, metrics, and the exact recipe in url. engine records execution provenance; mode records dataset provenance.

ModelResult

ModelResult(model, score, prompt_tokens, completion_tokens, total_tokens, cost_usd, failures=0, name=None, metrics=())

Per-call-slot score and accounting summary. Usage remains zero until the selected production engine reports it.

RunFailure

RunFailure(question_id, model, code, message, name=None)

Structured question/model failure retained on a Run.

Errors and metadata

ScreamingFaceError

Base exception for typed SDK failures.

EngineError

The engine rejected an expression or returned an invalid result. Carries code, optional status_code, and optional request_expression.

EngineUnavailable

The explicitly configured HTTP URL4 engine could not be reached.

DatasetUnavailable

A live or gated benchmark cannot be loaded in the current environment.

__version__

The installed SDK version string. Current documentation targets 0.2.0.

Replacing deterministic leaves

ScreamingFace already does

  • compile shareable and concrete URL4 expressions;
  • send one complete expression through the engine port;
  • validate panel/fusion result envelopes;
  • reduce locally or represent a model reducer in URL4;
  • load benchmarks, grade answers, and calculate baseline/gain;
  • record engine and dataset provenance separately.

A production URL4 engine must

  • accept GET /v1?q=<expression>;
  • register the required /provider/model routes;
  • translate generic parameters and tools for its provider adapter;
  • contact AI Gateway internally when that is its chosen backend;
  • preserve intent/context semantics and labeled result fields;
  • run repeated DRACO judge calls as independent samples;
  • accept real-size expressions over GET or agree a URL4-compatible size strategy;
  • eventually report usage, cost, failures, and tool telemetry.
The SDK does not need an AI Gateway URL, provider key, or gateway client. Switching from deterministic leaves to production execution is an engine-configuration change: sf.config("https://your-url4-engine.example").
